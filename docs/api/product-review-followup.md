# 상품·관심상품 리뷰 후속 기록

기준일: 2026-07-27

## 반영 내용

- 비인증 상품 상세는 `ON_SALE`만 반환하며 판매자는 인증된 전용 경로에서 자신의 비공개 상품을 조회한다.
- 관심상품 동시 중복 등록은 MySQL `INSERT IGNORE`와 유니크 키로 멱등 처리한다. 후속 조회의 비관적 잠금과 매물·카테고리 fetch join을 제거해 독립 요청의 잠금 범위를 넓히지 않는다.
- 상품·관심상품 OpenAPI 응답을 실제 `{ "data": ..., "meta": ... }` 구조와 일치시켰다.
- 상품 목록의 체크리스트 집계와 썸네일을 배치 조회해 100건 기준 예상 최대 약 402쿼리를 4쿼리로 줄였다.
- 모델 목록과 하위 카테고리는 `parent`를 entity graph로 함께 조회한다. MySQL 통합 테스트 기준 모델 페이지는 count 포함 최대 2쿼리, 하위 카테고리는 1쿼리다.
- `manufacturerId`, `verificationStatus`, 허용된 `sort` 조건을 실제 DB 조회에 적용한다.
- 기존 카탈로그의 `manufacturer_id`는 정규화한 제조사명의 CRC32로 backfill하고 신규 모델 생성에도 같은 규칙을 적용한다.
- 신규 모델의 지원 용량은 양수 검증, 중복 제거, 오름차순 CSV로 저장한다. 기존 지원 용량은 근거 없이 추정하지 않고 카탈로그 정비 시 채운다.
- 상태 없는 판매자 목록용 `(seller_id, deleted_at, updated_at)`과 상태별 목록용 `(seller_id, status, deleted_at, updated_at)` 인덱스를 각각 둔다.
- 애플리케이션 시간대는 `APPLICATION_TIME_ZONE`으로 명시하며 기본값은 `Asia/Seoul`이다. 상품 API 시각은 `+09:00` 계약을 사용한다.
- 상품 수정 요청은 설명·색상·용량의 명시적 `null`을 구분해 값을 비울 수 있다.
- 상품·관심상품 운영 로그에서 `sellerId`, `memberId` 필드를 제거했다.

## 수치 및 검증

- 백엔드 단위·컨트롤러 테스트: 133건 통과
- 실제 MySQL 통합 테스트: 13건 통과
- 프론트 테스트: 17개 파일, 38건 통과
- 프론트 빌드: 432개 모듈, JavaScript gzip 167.50 kB
- 백엔드 `bootJar`, JaCoCo 리포트, Spotless 검사 통과
- 프론트 lint와 프로덕션 build 통과
- OpenAPI 최신 소스 재생성 및 JSON 구조 검증

## 트러블슈팅

1. 통합 테스트 정리 단계에서 자기참조 카테고리의 부모·자식을 한 SQL로 삭제하자 MySQL 외래키 검증이 실패했다. 자식을 먼저 삭제하고 부모를 삭제하도록 순서를 분리했다.
2. Windows 샌드박스에서 Vite/esbuild가 상위 경로를 읽지 못해 test/build 설정 로딩이 실패했다. 동일 명령을 허용된 권한으로 재실행해 코드 문제가 아님을 확인했고 모두 통과했다.
3. 최초 MR CI의 Secret 검사에서 EC2 DNS 연결이 일시 실패했으며 재시도로 전체 파이프라인 통과를 확인했다. 이번 갱신 후 새 파이프라인을 다시 확인한다.

## 배포·롤백 주의

- `V20260727__extend_product_fields.sql`은 아직 `dev`에 병합되지 않은 동일 기능 브랜치의 마이그레이션이므로 이 MR 안에서 보완했다.
- 마이그레이션은 컬럼·인덱스 추가와 `manufacturer_id` backfill을 포함한다. 롤백 시 애플리케이션을 이전 버전으로 되돌릴 수 있지만 DB 컬럼·인덱스 제거는 별도 승인된 후속 마이그레이션으로 수행한다.
- 기존 `supported_storage_gb`의 미확인 값은 빈 상태를 유지하므로 운영 카탈로그 데이터 정비가 별도로 필요하다.
