# 관심 상품 API 구현 기록

## 범위

P-23 관심 상품 등록·목록 조회·해제를 기존 `wishlist` 테이블과 연결한다.

## API 계약

| Method | Path | 동작 |
| --- | --- | --- |
| `POST` | `/api/v1/products/{productId}/favorites` | 신규 등록은 201, 중복 등록은 기존 결과와 200 반환 |
| `GET` | `/api/v1/members/me/favorites?page=0&size=20` | 현재 회원의 관심 상품을 최신순으로 조회 |
| `GET` | `/api/v1/products/{productId}/favorites/me` | 현재 회원의 관심 상품 등록 상태 조회 |
| `DELETE` | `/api/v1/products/{productId}/favorites` | 등록 여부와 무관하게 멱등하게 204 반환 |

모든 API는 회원 JWT 인증이 필요하다. 등록·상태·목록 응답은 공통 `{ data, meta }` 계약을
OpenAPI에도 동일하게 선언한다. 관심상품 등록과 목록 노출은 공개 판매 중인 `ON_SALE` 상품으로
제한한다.

## 트러블슈팅 기록

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| 기능 브랜치 생성 실패 | `.git` 쓰기가 제한된 실행 환경 | 승인된 Git 실행으로 `feat/wishlist` 생성 |
| 백엔드 최초 테스트 실행 실패 | Gradle 9.6.1 배포본이 로컬에 없어 네트워크 다운로드 필요 | 승인된 네트워크 실행 후 테스트 환경 구성 |
| 백엔드 테스트 컴파일 실패 | 테스트 픽스처가 존재하지 않는 `SMARTPHONE_BAR` enum 사용 | 실제 enum인 `SMARTPHONE`으로 수정 |
| 프론트 명령 실행 실패 | PowerShell이 `npm.ps1` 실행을 차단 | 동일 npm의 `npm.cmd` 진입점 사용 |
| 프론트 테스트 수집 실패 | 최신 잠금 파일의 Sentry 패키지가 로컬 의존성에 미설치 | `npm ci`로 잠금 파일 기준 412개 패키지 복원 |
| 동시 중복 등록 시 500 가능성 | MySQL `REPEATABLE READ`에서 유니크 충돌 후 외부 트랜잭션의 기존 스냅샷으로 재조회 | `REQUIRES_NEW` 안에서 `INSERT IGNORE` 후 잠금 조회하여 두 요청 모두 같은 관심상품을 반환 |
| 목록 페이지 메타데이터 유실 | 공통 프론트 API client가 `data`만 반환 | 페이지 API는 `{ data, meta }` 전체를 보존하고 화면에 이전·다음 탐색 제공 |
| 프로젝트 Secret 스크립트 실행 실패 | 현재 Windows 환경에서 Bash 인스턴스 생성 권한 없음 | 같은 파일명 규칙과 변경 파일 내용 규칙을 PowerShell로 재현해 검사 |

## 검증 및 남은 위험

- 백엔드 전체 단위·컨트롤러 테스트: 122개 통과.
- 관심 상품 MySQL 저장소 통합 테스트를 포함한 DB 통합 테스트: 8개 통과.
- 관심 상품 동시 등록은 실제 MySQL의 독립 트랜잭션 2개로 검증했으며 생성 결과는 `1건 생성 + 1건 기존 반환`이었다.
- 프론트 전체 테스트: 15개 파일, 34개 통과.
- 프론트 lint: 통과.
- `npm ci` 감사 결과 기존 의존성에서 취약점 17건(중간 2, 높음 14, 치명적 1)이 보고되었다. 이번 기능에서 버전을 임의 변경하지 않았으며 별도 의존성 정비가 필요하다.
- 백엔드 `bootJar`, Jacoco 리포트, Spotless 검사: 성공.
- OpenAPI export: 성공, 관심 상품 경로 3개와 동작 4개 및 공통 응답 wrapper 반영.
- 프론트 프로덕션 빌드: 430개 모듈 변환, JS gzip 166.36 kB.
- 브라우저 확인: 비인증 접근이 로그인으로 전환됐고 콘솔 오류 0건. 인증 후 데이터 상태는 자동 화면 테스트로 검증했다.
- Secret 검사: 변경 범위 내용 검사 잠재 Secret 0건, 커밋 가능 파일 521개 중 `.env`·키·인증서 확장자 0건.
