# 상품 카탈로그 기준 데이터와 RTC 보완

## 상품 카탈로그

`V20260801__seed_product_catalog_reference_data.sql`은 빈 운영 DB에서도 상품 등록 흐름이
동작하도록 다음 MVP 기준 데이터를 추가한다.

- 최상위 기기 카테고리 4개
- 지원 기기 모델 7개
- 모델별 `PUBLISHED` 체크리스트 템플릿 7개와 항목 32개
- 제조사·기기 유형별 계정 제거 및 초기화 가이드 7개

기준 데이터는 카테고리 이름, 모델 코드, 템플릿 버전을 기준으로 기존 행이 있으면
다시 넣지 않는다. 노트북 모델에는 batteryreport와 dxdiag 진단 파일 항목을 추가한다.

### 상품 등록 모델 선택

- `GET /api/v1/device-models` 결과는 프론트에서 제조사별로 그룹화하고 제조사·모델명·모델 코드로 검색한다.
- `POST /api/v1/device-models`는 ACTIVE 판매자가 목록에 없는 Windows·Linux 노트북 모델을 직접 등록할 때 사용한다.
- 제조사와 모델명이 같은 활성 모델이 이미 있으면 기존 모델을 반환한다.
- 모델 코드를 입력하지 않으면 제조사·모델명·OS 조합으로 안정적인 `CUSTOM-*` 코드를 생성한다.
- 휴대폰·폴더블·태블릿의 직접 입력은 게시 체크리스트 템플릿이 필요하므로 이번 범위에서 제외한다. 해당 기기는 기존 기준 모델과 `PUBLISHED` 템플릿을 사용한다.
- AI 생성, 템플릿 승인·버전·스냅샷 정책은 검수 도메인이 소유한다.

## RTC 요구사항 점검 결과

기존 구현에서 통화 요청·수락, WebRTC 영상·음성, 체크리스트 조회, 실시간 특정 부위
요청, 종료 결과 저장, ICE 재시작과 재입장, Coturn 및 모니터링 구성을 확인했다.
전체 통화 녹화 기능은 MVP 범위에 포함하지 않는다.

이번 보완에서는 다음 실패 경로를 추가했다.

- 세션 TTL 경과 시 `RTC003`으로 재입장을 거절하고 예외 트랜잭션의 상태 변경은 롤백
- 종료 세션 재입장과 권한 없는 접근을 RTC 전용 오류로 구분
- 중복 체크리스트 결과로 인한 DB 제약조건 500 방지
- 종료 API 재호출 시 기존 결과를 유지하는 멱등 처리

RTC 전용 오류 코드는 다음과 같다.

| 코드 | 의미 |
| --- | --- |
| `RTC001` | 세션 없음 |
| `RTC002` | 세션 접근 권한 없음 |
| `RTC003` | 세션 만료 |
| `RTC004` | 이미 종료된 세션 |
| `RTC005` | 현재 상태에서 처리 불가 |
