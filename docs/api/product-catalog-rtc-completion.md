# 상품 카탈로그 기준 데이터와 RTC 보완

## 상품 카탈로그

`V20260801__seed_product_catalog_reference_data.sql`은 빈 운영 DB에서도 상품 등록 흐름이
동작하도록 다음 MVP 기준 데이터를 추가한다.

- 최상위 기기 카테고리 4개
- 지원 기기 모델 7개
- 모델별 `PUBLISHED` 체크리스트 템플릿 7개와 항목 32개
- 제조사·기기 유형별 계정 제거 및 초기화 가이드 7개

기준 데이터는 카테고리 이름, 모델 코드, 템플릿 버전을 기준으로 기존 행이 있으면
다시 넣지 않는다. 모든 기기 유형에 공통으로 `SYS-003`(기기 정보 화면, `evidence_type=PHOTO`,
`automation_type=OCR`) 항목을 추가하고, 노트북 모델에는 여기에 더해 `BAT-005`(배터리 리포트)와
`DXD-006`(dxdiag) 진단 파일 항목을 추가한다.

노트북은 실제 등록 시점에는 이 시딩 템플릿이 아니라 `LaptopChecklistPolicy`가 그때그때 만드는
노트북 전용 체크리스트를 스냅샷으로 쓴다([laptop-checklist-generation.md](laptop-checklist-generation.md)
참고). 이 정책에도 동일한 목적의 OCR 항목(`LAP-SCR-013`, 설정 정보 화면)이 있어 코드/이름은 다르지만
기능은 같다. 반대로 스마트폰·태블릿(폴더블 포함)은 실제 등록 시에도 이 시딩 템플릿을 그대로 스냅샷으로
쓰므로, `SYS-003`이 그 기기들에서 실제로 동작하는 OCR 항목이다.

## RTC 요구사항 점검 결과

기존 구현에서 통화 요청·수락, WebRTC 영상·음성, 체크리스트 조회, 실시간 특정 부위
요청, 종료 결과 저장, ICE 재시작과 재입장, Coturn 및 모니터링 구성을 확인했다.
전체 통화 녹화 기능은 MVP 범위에 포함하지 않는다.

이번 보완에서는 다음 실패 경로를 추가했다.

- 세션 TTL 경과 시 `RTC003`으로 재입장을 거절하고 예외 트랜잭션의 상태 변경은 롤백
- 종료 세션 재입장과 권한 없는 접근을 RTC 전용 오류로 구분
- 중복 체크리스트 결과로 인한 DB 제약조건 500 방지
- 종료 API 재호출 시 기존 결과를 유지하는 멱등 처리

RTC 전용 오류 코드는 다음과 같다.

| 코드 | 의미 |
| --- | --- |
| `RTC001` | 세션 없음 |
| `RTC002` | 세션 접근 권한 없음 |
| `RTC003` | 세션 만료 |
| `RTC004` | 이미 종료된 세션 |
| `RTC005` | 현재 상태에서 처리 불가 |
