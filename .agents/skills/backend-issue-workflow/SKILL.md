# 백엔드 이슈 처리

## 목적

백엔드 변경을 요구사항과 계약에 맞게 구현하고 검증 근거를 남긴다.

## 먼저 읽을 근거

1. 루트와 `backend/AGENTS.md`
2. 이슈의 요구사항과 완료 조건
3. 관련 도메인 코드와 인접 테스트
4. 필요한 경우에만 `docs/api`, `docs/adr`와 연결된 Notion 문서

## 허용되는 수정 범위

이슈와 직접 관련된 백엔드 코드, 테스트, API·ADR 문서를 수정한다. 운영 설정, Secret, migration, 배포 실행은 승인 없이는 변경하지 않는다.

## 작업 순서

1. 완료 조건과 변경 범위를 요약한다.
2. `/api/v1` 경로와 공통 응답 계약을 확인한다.
3. 도메인 내부에 최소 변경으로 구현한다.
4. 정상·실패 경로 테스트를 추가한다.
5. API 계약 변경 시 문서를 함께 갱신한다.
6. `gradle test`와 `gradle bootJar`를 실행한다.

## 산출물과 완료 기준

변경 파일과 이유, 테스트 결과, 완료 조건 충족 여부, 남은 위험을 보고한다. 필수 검증이 실패했거나 실행되지 않았으면 완료로 표시하지 않는다.

## 금지사항

Secret 조회·출력, 운영 DB 변경, 위험 명령, 테스트·품질 기준 우회를 금지한다.
